## 一句话定位

IPFS（InterPlanetary File System，星际文件系统）是一个点对点的去中心化文件存储与分发协议，用"内容寻址"取代传统的"位置寻址"——文件按其内容的哈希来标识和获取，而非按它在哪台服务器上，是构建去中心化 Web 的重要基础设施。

## 诞生背景

2015 年由 Protocol Labs（Juan Benet）发起。传统 Web 用 URL 定位（HTTP 按"位置"找文件：某服务器的某路径），一旦服务器下线链接就失效，且高度中心化。IPFS 提出按"内容"寻址：只要内容存在于网络中任意节点，就能取到，天然抗审查、防失效。

## 核心架构

- **内容寻址（CID）**：文件以内容哈希（CID）标识，内容变则地址变
- **P2P 网络**：节点间直接交换数据块（受 BitTorrent 启发）
- **DHT 分布式哈希表**：定位谁持有某内容
- **Merkle DAG**：用默克尔有向无环图组织数据，天然去重、可验证
- **Pinning**：节点可"钉住"内容以持久保存

## 关键设计决策

1. **内容寻址取代位置寻址**：按"是什么"而非"在哪里"找文件，从根本上抗失效、抗审查、可去重。
2. **P2P 去中心化**：没有中心服务器，内容由网络中的节点共同持有和分发。
3. **可验证性**：基于哈希的寻址天然保证内容完整性，取到的一定是对的。

## 生态位置

去中心化存储的代表协议，Web3 基础设施之一。常用于 NFT 元数据、去中心化网站、抗审查内容存储。相关：Filecoin（同团队，给 IPFS 加激励层）、Arweave（永久存储）。与传统中心化的 HTTP/云存储（S3）形成范式对立。

## 我的评价

IPFS 提出的"内容寻址"是一个深刻的思想——它挑战了 Web 最基础的假设：*为什么我们要按"文件在哪台服务器"来找它，而不是按"文件是什么"？* 内容寻址天然解决了链接失效（内容在就能取到）、防篡改（哈希验证）、去重等一系列问题。它未必会取代 HTTP（中心化仍有其效率优势），但作为"另一种可能"，它和 Mastodon、Matrix 一道，共同守护着"Web 可以更去中心化"的理想。
