## 一句话定位

dbt（data build tool）是数据转换工具，让数据分析师用 SQL + 软件工程最佳实践（版本控制、测试、文档、模块化）在数据仓库里做数据建模，把混乱的数据转换脚本变成规范可维护的工程，掀起了"分析工程（Analytics Engineering）"的浪潮。

## 诞生背景

2016 年发布，顺应云数据仓库（Snowflake、BigQuery）兴起带来的 ELT 转变。过去数据转换是零散、无版本、难测试的 SQL 脚本；dbt 把软件工程的规范引入数据转换环节，让"数据建模"成为一门有章可循的工程。

## 核心架构

- **SQL + Jinja 模板**：用增强的 SQL 定义数据模型，支持复用与参数化
- **DAG 依赖**：自动解析模型间依赖，按序构建
- **内建测试**：对数据做断言测试（唯一、非空、关系等）
- **自动文档**：从代码生成数据模型文档与血缘图
- **版本控制友好**：模型即代码，纳入 Git 管理

## 关键设计决策

1. **把工程规范带入数据转换**：版本控制、测试、文档、模块化——让 SQL 转换像写软件一样规范。
2. **只做 T（Transform）**：专注 ELT 中的转换环节，在数据仓库内用 SQL 完成建模。
3. **SQL 优先**：让懂 SQL 的分析师就能做数据工程，无需重度编程。

## 生态位置

现代数据栈（Modern Data Stack）的核心，"分析工程"这一新角色的代表工具。常与 Airbyte/Fivetran（数据集成 EL）、Snowflake/BigQuery（数据仓库）、Airflow（编排）组合。它定义了云数仓时代数据转换的标准范式。

## 我的评价

dbt 的贡献是"把软件工程的成熟实践迁移到数据领域"——它敏锐地发现，数据转换长期缺乏版本控制、测试、文档这些软件工程早已标配的东西。它甚至催生了一个新职业"分析工程师"。这印证了一个反复出现的模式：**当一个领域成熟到一定程度，把邻近成熟领域（软件工程）的最佳实践引入，就能带来一次跃升**——正如 MLflow 之于 ML、GitOps 之于运维。
