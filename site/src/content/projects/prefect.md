## 一句话定位

Prefect 是 Python 原生的现代工作流编排工具，用简单的装饰器（`@flow`、`@task`）就能把普通 Python 函数变成可调度、可重试、可观测的工作流，主打"动态、灵活、以代码为中心"，是 Airflow 的现代轻量替代。

## 诞生背景

2018 年由 Airflow 的资深用户创立，口号一度是"负工程（negative engineering）"——即帮你处理"任务失败了怎么办、重试、超时、告警"这些编排中最烦人的部分。它认为 Airflow 太重、DAG 太僵化，想要更 Pythonic、更动态的编排体验。

## 核心架构

- **装饰器即工作流**：`@flow`/`@task` 把普通函数变成编排单元
- **动态工作流**：支持运行时决定的动态任务（Airflow 早期难做）
- **自动重试与状态**：内建重试、超时、缓存、状态管理
- **混合执行**：编排逻辑与执行环境分离，代码在你的基础设施跑
- **可观测 UI**：运行状态、日志、调度可视化

## 关键设计决策

1. **Python 原生 + 装饰器**：把编排能力做成对普通 Python 代码的最小侵入增强。
2. **动态优于静态 DAG**：支持运行时动态生成任务，比 Airflow 静态 DAG 更灵活。
3. **专注"负工程"**：把重试、超时、告警这些编排脏活自动化，让人专注业务逻辑。

## 生态位置

现代数据/工作流编排的代表之一。与 Airflow（老牌、静态 DAG、生态大）、Dagster（资产为中心）三分现代编排市场。Prefect 以"Pythonic、动态、轻量"见长，适合灵活多变的编排需求。

## 我的评价

Prefect 提出的"负工程"概念很精辟——它点出编排工具的真正价值不在"跑任务"（那很简单），而在优雅地处理"任务失败、重试、超时、告警"这些**必要却烦人的边角**。它和 Airflow、Dagster 的三方竞争也很有代表性：同一个问题（数据编排），分别以"任务/DAG""资产""动态代码"为核心抽象，各自吸引不同偏好的团队——再次说明核心抽象的选择定义了一个工具的气质。
