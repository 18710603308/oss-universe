# 寻找适合的开源项目

> 来源：[GitHub Docs - Finding ways to contribute](https://docs.github.com/en/get-started/exploring-projects-on-github/finding-ways-to-contribute-to-open-source-on-github)

---

## 从哪里开始

不需要过度思考你的第一个贡献应该是什么。从你日常使用的项目开始，当你发现某些东西可以改进时，就去行动。

> 研究表明，开源中 28% 的非正式贡献是文档相关的，如修复 typo、调整格式、翻译等。

## 发现项目的渠道

### 从你使用的软件开始

最好的入手项目就是你日常使用的工具和框架。你已经了解它们，更容易发现问题和改进点。

### GitHub 平台资源

| 资源 | 链接 | 说明 |
|------|------|------|
| GitHub Explore | https://github.com/explore | 根据你的兴趣推荐项目 |
| GitHub Trending | https://github.com/trending | 每日/每周热门项目 |
| GitHub Topics | https://github.com/topics/你感兴趣的话题 | 按话题浏览 |
| 仓库 /contribute 页面 | `仓库URL/contribute` | 查看新手友好 Issue |

### 专门为新手设计的平台

| 平台 | 说明 |
|------|------|
| [First Timers Only](https://www.firsttimersonly.com/) | 收集对新手友好的 Issue |
| [Good First Issues](https://goodfirstissues.com/) | 按语言筛选适合新手的 Issue |
| [Up For Grabs](https://up-for-grabs.net/) | 欢迎新贡献者的项目列表 |
| [First Contributions](https://github.com/firstcontributions/first-contributions) | 专门的新手练习仓库 |
| [CodeTriage](https://www.codetriage.com/) | 每天推送需要帮助的 Issue |
| [OpenSauced](https://opensauced.pizza/) | 开源贡献追踪和发现平台 |

### 关键标签

在 GitHub Issues 中搜索这些标签：
- `good first issue` — 官方推荐的新手任务
- `help wanted` — 维护者明确需要帮助
- `beginner` / `easy` / `starter` — 难度较低的任务
- `documentation` — 文档相关任务
- `bug` — 需要修复的问题

## 评估项目的清单

在投入时间之前，先检查项目是否适合贡献：

### ✅ 基本条件

- [ ] 有开源协议（`LICENSE` 文件）
- [ ] 有 `README` 说明文档
- [ ] 有 `CONTRIBUTING` 贡献指南

### ✅ 活跃度

- [ ] 最近一次提交在 3 个月内
- [ ] 有多个活跃贡献者
- [ ] Issue 有人回复（不是石沉大海）
- [ ] PR 有人审查和合并
- [ ] 最近有 Issue 被关闭

### ✅ 友好度

- [ ] 维护者对问题回复态度友好
- [ ] Issue 和 PR 中有建设性讨论
- [ ] 有 `good first issue` 标签的 Issue
- [ ] PR 会收到有帮助的 Review
- [ ] 有行为准则（`CODE_OF_CONDUCT`）

### ⚠️ 警告信号

- 长期没有新提交
- 大量 Issue 和 PR 没有回应
- 讨论中充满争吵或不友善言论
- 没有任何文档

## 贡献方式

找到项目后，你可以通过多种方式贡献：

### 入门级贡献（推荐新手）

1. **修复文档** — 修正错别字、补充说明、更新过时内容
2. **改进 README** — 添加使用示例、截图
3. **添加翻译** — 将文档翻译为其他语言
4. **复现 Bug** — 验证并补充 Bug 报告的信息

### 进阶贡献

5. **修复 Bug** — 根据 Issue 修复代码问题
6. **添加测试** — 提高测试覆盖率
7. **改进工具** — CI/CD、Linter 配置
8. **开发功能** — 实现新特性（建议先在 Issue 讨论）

### 非代码贡献

9. **回答问题** — 在 Issue/Discussion 中帮助其他用户
10. **Review PR** — 审查他人的代码修改
11. **整理 Issue** — 标记重复、添加标签
12. **设计** — UI/UX 改进、Logo 设计

## 实践行动计划

1. **第一周**：在 first-contributions 仓库完成你的第一个 PR
2. **第二周**：在你常用的项目中找到一个文档 Issue 并修复
3. **第三周**：尝试复现一个 Bug 并补充信息
4. **第四周**：挑战一个 `good first issue` 的代码修复
